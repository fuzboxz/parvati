## Findings

### 1. Host parameter context menus — HIGH value / LOW effort (recommended)
API verified (JUCE 9.0.1): `AudioProcessorEditor::getHostContext()` (`juce_AudioProcessorEditor.h:209`, set by the VST3 wrapper at `juce_audio_plugin_client_VST3.cpp:2324`) returns `AudioProcessorEditorHostContext*` whose `getContextMenuForParameter(const AudioProcessorParameter*)` (`juce_AudioProcessorEditorHostContext.h:65`) yields `HostProvidedContextMenu` with `getEquivalentPopupMenu()` and `showNativeMenu(Point<int> posRelativeToEditorTopLeft)` (host context file lines 39-51). VST3-only path; requires host `IComponentHandler3` (`VST3.cpp:1899-1927` — Cubase yes, Reaper's VST3 partly). Pattern for `ParamControl::showContextMenu` (`PluginEditor.cpp:1307`): the editor is already in hand at line 1313 (`dynamic_cast<ParvatiEditor*>(getParentComponent())`). Either (a) preferred: build the juce PopupMenu as today, then if `auto* ctx = ed->getHostContext()` and `auto hostMenu = ctx->getContextMenuForParameter(processor_.getApvts().getParameter(desc_.paramID))`, append Reset/Randomize into `hostMenu->getEquivalentPopupMenu()` and `showMenuAsync`; or (b) simplest: `hostMenu->showNativeMenu(ed->getLocalPoint(this, juce::Point<int>(0, getHeight()/2)))` and fall back to the existing menu when `getHostContext()` is null (AUv3/standalone). Wrap ParamControl's right-click AND the existing touch long-press path (line 1203) — one function, both benefit.

### 2. Parameter value-to-text — HIGH value / LOW effort (recommended)
`ParameterLayout.cpp:589-596`: `AudioParameterInt` created bare; VST3 hosts render raw `0..127` (wrapper's `Parameter::toString` calls `param.getText` at `VST3.cpp:985-991` → `juce_AudioParameterInt.cpp:76` → `stringFromIntFunction`). Fix: `.withStringFromValueFunction()` on `AudioParameterIntAttributes` (`juce_AudioParameterInt.h:44`; base at `juce_RangedAudioParameter.h:59-66`, signature `String(Value, int length)`; pair with `withValueFromStringFunction` (`Value(const String&)`) so hosts that parse typed text work — Cubase parameter entry, Bitwig). `SynthParamLabels::paramValueTextSynth` (`SynthParamLabels.cpp:95`) maps 1:1: wrap as `[id](juce::Value v, int){ return paramValueTextSynth(id, (double) v.getValue()); }`; use `ui/FxSlotLabels.cpp`'s `paramValueText` for `isFx` descriptors. Two cautions: (a) `toString` may be called off the message thread — the LUT lookups (`SynthParamLabels.cpp:161-168`) are constexpr math, safe, but keep the formatter out of any component-touching code; (b) it lives in `ui/` — moving it (or forwarding) to a UI-free TU keeps the processor build clean. `AudioParameterChoice` already provides text via its choice list — no action. `ParameterID { d.paramID, 1 }` (lines 583/590/596) is already version-1 — keep when touching.

### 3. Parameter grouping — MEDIUM value / LOW effort
`AudioProcessorValueTreeState::ParameterLayout::add` accepts `std::unique_ptr<AudioProcessorParameterGroup>` (`juce_AudioProcessorValueTreeState.h:174-186`); VST3 wrapper maps group names → Units (`VST3.cpp:430-441`), so Bitwig/Reaper/Cubase get tree-structured parameter browsers. `createParvatiParameterLayout` (`ParameterLayout.cpp:575-600`) currently adds flat. Group by the existing `sectionForId` prefix rules (`PluginEditor.cpp:83-135`): Osc/Mix/Filter/Envelopes/LFOs/ModMatrix/Modifiers/Seq/Arp/FX/FXMod/Global/Part. Order within groups must stay identical to the descriptor table to keep VST3/AU parameter indices stable across versions.

### 4. Programs — NOT recommended
`getNumPrograms()=1` (`PluginProcessor.h:74-78`) is the correct APVTS convention; VST3 wrapper synthesizes a "Factory Presets" unit from `getProgramName` (`VST3.cpp:464-484`) — harmless with 1 program. Exposing factory banks as host programs means `setCurrentProgram` must `replaceState` the whole APVTS (multi-part .MUL state, `PluginProcessor.cpp:1684+`), racing host UI/undo, duplicating the embedded PresetBrowser (`ui/PresetBrowser.h:207-216`, Factory ▸ A/B/F/S ▸ .PRO). Pros: host preset menus / AU factory presets. Cons: state/threading complexity, two sources of truth, VST3 program-list deprecation. Keep 1 program; if host-visible factory presets are wanted, ship .vstpreset/.aupreset files instead.

### 5. VST3_CATEGORIES — no action
`CMakeLists.txt:220-237` sets `IS_SYNTH TRUE` and no `VST3_CATEGORIES` override; JUCEUtils.cmake:1869-1872 defaults to `Instrument Synth`. Nothing else missing in `juce_add_plugin` (MIDI in ✓, non-MIDI-effect ✓, manufacturer/plugin codes valid). `COPY_PLUGIN_AFTER_BUILD FALSE` is a dev choice only.

### 6. Other host-facing items
- **`getTailLengthSeconds()=0.0`** (`PluginProcessor.h:54`) — MEDIUM. The synth has echo/room/spring FX; hosts (Logic/Cubase offline bounce) truncate tails at 0. Report a modest worst-case tail (e.g. FX-dependent, ~4 s) or at least a small constant.
- **`processBlockBypassed` not overridden** — LOW. Default `processBypassed` (`juce_AudioProcessor.cpp:589-603`) jasserts when `getLatencySamples()>0` (debug builds) — Parvati reports nonzero latency with filter oversampling (`PluginProcessor.cpp:431-443`). Override to clear the buffer (silence is right for a bypassed synth) and keep latency reporting consistent; VST3 host bypass routes through the wrapper's auto-added bypass param (`VST3.cpp:674-680`).
- `supportsMPE()=true` (`PluginProcessor.h:63`) — justified by per-channel routing; fine. Double precision not overridden — fine (flag defaults false). `getState/setStateInformation` conventions fine. No bypass parameter in APVTS — correct; wrapper supplies one.
